# Preflight — 완료 선언 전 품질 게이트

## 개요

이 저장소에서 "완료"는 감상이 아니라 **아래 표의 실행 결과**다.
게이트를 돌리지 않은 완료 선언, 표 없는 완료 선언은 금지된다.
근거 규칙과 기준선은 [CLAUDE.md](../../../CLAUDE.md) §3.

## 언제 쓰나

- 커밋 직전 (항상)
- 사용자에게 "끝났습니다"라고 말하기 직전 (항상)
- 파서/렌더러를 건드린 뒤 (3단계 포함 필수)

언제 안 쓰나: 문서만 바꿨을 때는 1·5단계만으로 충분하다.

## 절차

### 1. 범위·민감파일 검사

```bash
git status --short
git diff --stat
```

- 의도한 파일만 변경됐는가? 무관한 파일이 있으면 먼저 원복.
- `nul`, `NUL` 파일이 생겼으면 당신의 셸 실수다(CLAUDE.md M1). 삭제하고 원인 명령을 고쳐라.
- staged 목록(`git diff --cached --name-only`)에 `reports/`, `*.docx`, `GPT_deep/` 이 있으면 즉시 unstage.

### 2. 테스트 / 린트 / 타입

```bash
uv run pytest -q | tail -3
uv run ruff check . | tail -1
uv run mypy ib_renderer.py md_formatter.py md_parser.py md_to_word.py | tail -1
```

| 검사 | 통과 기준 (기준선: 2026-07-07, v1.0.3) |
|------|------------------------------------------|
| pytest | `0 failed`. passed 개수 ≥ 228. 감소했다면 사유를 보고서에 명시 |
| ruff | 총 에러 ≤ **28**. 초과분은 당신 것 — 수정 |
| mypy | 총 에러 ≤ **22**. 초과분은 당신 것 — 수정 |

총계가 기준선 이하라도, 당신이 **수정한 파일**에 에러가 있으면 각각에 대해
그 에러가 당신이 만든 줄인지 diff로 확인한다. 당신 줄이면 수정, 기존 것이면 건드리지 않는다(M12).
기준선 수치를 개선했다면 CLAUDE.md §3-D와 이 파일의 수치를 같은 커밋에서 갱신한다.

### 3. docx 게이트 — 파서/렌더러/포매터를 건드렸을 때만

```bash
uv run pytest tests/test_docx_gates.py -q
```

- 통과: 전부 통과 (스냅샷 + XML 게이트).
- 실패 시: 실패한 테스트 출력을 읽는다. 당신이 바꾼 요소 타입과 관련 있으면 회귀다 — 수정하라.

### 4. 스모크 변환 (end-to-end)

```bash
uv run md_to_word.py tests/웅진_계열사.md smoke_output_pf.docx && rm smoke_output_pf.docx
```

exit 0. 실패하면 스위트가 그린이어도 완료가 아니다.

### 5. 문서 드리프트 — CLI·기능·플래그를 바꿨을 때만

```bash
grep -c '^## ' README.md README.ko.md   # 두 값이 같아야 함
grep -n "당신이 바꾼 플래그명" README.md README.ko.md AGENTS.md
```

새 플래그·기능이 세 문서에 모두 반영됐는가? 하나라도 빠지면 같은 커밋에서 채운다.

### 6. 결과 보고 (필수 양식)

```
## Preflight 결과
| 검사 | 결과 | 판정 |
|------|------|------|
| 범위/민감파일 | 변경 파일 N개, 민감파일 없음 | PASS |
| pytest | 28X passed, 0 failed | PASS |
| ruff | 총 XX (기준선 28) | PASS |
| mypy | 총 XX (기준선 22) | PASS |
| docx 게이트 | test_docx_gates.py 전부 통과 | PASS / 해당없음 |
| 스모크 | exit 0 | PASS |
| 문서 동기화 | README×2+AGENTS 반영 | PASS / 해당없음 |
```

하나라도 FAIL이면: 수정 후 **전체를 처음부터 재실행**. 수정 2회 후에도 FAIL이면
CLAUDE.md §6 검증 실패 프로토콜(중단 + 보고)로 전환한다.

## 합리화 차단표

| 변명 | 현실 |
|------|------|
| "한 줄 수정이라 스킵해도 됨" | 이 저장소의 회귀는 대부분 한 줄에서 나왔다. 전체 스위트가 10초다. |
| "ruff 에러는 원래 있던 것" | 기준선 28 초과분과 당신 줄의 에러는 증명 가능하다. diff로 확인하라. |
| "테스트가 통과하니 스모크 불필요" | CLI 배선·인코딩·경로 버그는 단위 테스트 밖에서 터진다. |
| "문서는 나중에" | 이 저장소의 문서 드리프트(267 vs 284)가 그 "나중에"의 결과다. |

## 레드 플래그 — 이 생각이 들면 멈춰라

- "아마 통과할 것이다" → 실행하지 않았다는 뜻이다.
- "시간이 없으니 커밋부터" → 게이트 없는 커밋 금지.
- 표를 채우지 않고 "완료했습니다"를 쓰고 있다 → 되돌아가서 게이트 실행.
