이 문서는 로드맵 E10(DCM 차트)의 구현 검증 기록이다. 조사와 제안(시안 포함)은 저장소 밖 보고 폴더에서 했고, 소유자가 2026-11-14에 제안서의 질문 4개에 모두 추천안으로 답했다. 구조 검사 통과는 시각 검토 통과를 뜻하지 않으며, 한 검증과 하지 않은 검증을 나누어 적는다.

## 1. 바뀐 것과 그대로인 것

**바뀐 것(승인된 변화).**

- `charts: true`인 문서의 차트 모양: 강조색 하나(테마 `NAVY`)와 회색, 세로축 대신 막대 값, 0 기준선, 위쪽 한 줄 범례, 선 끝 이름표, 감소 막대 빗금, 흑백 밝기 차로 고른 색. 그림 높이 3.2인치 → 2.9인치(가로 막대·범위 막대는 항목 수에 비례), 그림은 왼쪽 정렬.
- 차트 제목·부제·주·출처가 그림 안 글자에서 Word 문단으로 바뀌었다. 앞말은 IB 프로필 `Note`/`Source`, 일반 프로필과 `mono` 테마 `주`/`자료`. 폭포 합계 기본 이름도 같은 규칙(`Total`/`합계`, 이전에는 언제나 `Total`).

**그대로인 것(테스트로 고정).**

- 차트가 없는 문서, `charts`가 꺼진 문서: 산출물 변화 없음. 기존 스냅숏 367개 가운데 바뀐 것은 `samples/qa/charts.md`의 것뿐이다(3절).
- `chart_style: classic`: 예전 키만 쓴 `bar`·`line`·`waterfall`은 예전 그림과 예전 문서 XML 그대로다. `render_chart_png` 본문은 한 글자도 바뀌지 않았고(`c97841c`와 비교), 스냅숏 묶음의 `classic-charts` 변형의 XML 파트 21개는 변경 전 `charts-on` 스냅숏과 바이트 단위로 같다. 그림 요소(막대 위치·높이·색, 선, 글자, 축 범위, 그림 크기·해상도)는 `tests/__snapshots__/test_chart_ib_style.ambr`에 고정했고, classic이 넣는 PNG가 `render_chart_png`의 출력과 같은지도 시험한다.
- 사양 오류 처리: strict 거부, 일반 모드는 코드 상자 + 진단. 새 거부 코드 없음.
- 대체 텍스트: 제목, 없으면 `Chart N`.
- 값의 배율: 바꾸지 않는다(`12.5`는 `percent`에서 `12.5%`). 형식 함수는 `format_value` 하나다.

## 4. 흑백 밝기 기준

테마 주색 하나에 회색(과 누적 막대에서는 주색의 옅은 색)을 붙인다. 회색은 검정과 흰색 사이 17단계, 주색의 옅은 색은 4단계 후보 중에서 흑백 밝기(ITU-R BT.601 luma, 0~255) 차이가 가장 큰 조합을 고른다. 기준값과 근거:

| 색 수 | 최소 밝기 차 기준 | 16단계 RGB 격자(4,913색) 최악값 |
|---|---|---|
| 2(비교 2계열, 강조 막대, 막대+선) | 60 | 60.0(규칙상 하한) |
| 3 | 50 | 비교 63.1, 누적 60.0 |
| 4 | 40 | 47.0 |
| 폭포 잔액 막대와 주색 | 45 | 45.0(규칙상 하한) |

근거: 1단계 제안서의 시안에서 지금 엔진의 IB 막대 두 계열(진청 42 vs 짙은 회색 64, 차이 22)과 폭포의 증가·감소(진청 42 vs 빨강 57, 차이 15)는 흑백 인쇄에서 구분되지 않았고, 차이 47 이상인 시안은 구분됐다. 4색에서 40은 주색이 중간 밝기일 때도 지킬 수 있는 값이다(격자 최악값 47). 같은 기준을 Hypothesis 속성 시험(임의 주색 300개)이 확인한다. 기준을 맞추지 못하는 조합이 생기면 회색 선택 규칙을 고친다(AGENTS.md).

계열이 4개를 넘는 비교 막대·선은 기준을 지킬 수 없어 그리되 렌더링 경고를 남긴다(거부하지 않는다: 지금 변환되는 문서를 거부하지 않기 위해). 누적 막대는 4개까지만 받는다(새 종류).

## 5. 참조 규칙(차트 문단 안의 `@tbl-…`/`@fig-…`)

차트 제목·부제·주·출처는 Word 문단이지만 **필드를 넣지 않고 글자로 둔 뒤 진단한다**(strict 거부). 근거:

- 차트 사양의 글자는 YAML 값이며, classic이 그림 안에 그리던 대로 Markdown이 아닌 일반 글자로 쓴다. E5는 일반 글자로 보이는 frontmatter 값을 "필드를 넣을 수 없는 자리"로 다룬다(`check_text(markdown=False)`).
- 제목은 그림의 대체 텍스트이기도 하다. E5는 그림 설명에 필드를 허용하지 않는다.
- 진단은 `TextParser.check_text`가 렌더 범위(reference scope) 안에서 하므로 풀리지 않는 참조가 strict를 조용히 통과하지 않는다. classic 차트는 이 글자를 그림 안에 그리므로 지금처럼 코드 블록 취급(읽지 않음)이다.
