## 2. 처리 기록

1. **4절(#21) Codex 리뷰 지적 5건을 반영했다.** 테스트를 먼저 쓴 뒤 고쳤고, `feat/converted-md-cleanup`를 그 위로 다시 맞췄다.
   - 결과: null style 값은 모두 설정 오류, `page_number`는 모든 줄바꿈 문자 거부, `label_color: ""`는 기본 회색, frontmatter `logo: ""`는 house 로고 제거(후속 리뷰 반영).
   - 3번(표지 뒤 가로 표): Word 16.0.20326에서는 수정 전후 모두 3쪽이고 쪽 이미지가 픽셀 단위로 같았다. 중복된 쪽 나누기는 다른 뷰어에서 빈 쪽이 될 수 있으므로, 가로 구역 직전의 단독 쪽 나누기 문단만 뺀다(쪽 나누기가 둘 이상이면 유지). 기존 샘플 출력은 모두 같다.
   - 원래 지적 내용:
     - (P2, 재현됨) `style: {page_number: null}`은 검증을 통과해 바닥글 렌더링에서 `TypeError`로 중단된다. null을 거부하거나 기본값으로 바꾼다.
     - (P2, 재현됨) `logo_width_mm: null`은 검증을 통과한다. 그러면 비strict에서는 로고가 빠지고 strict에서는 `NoneType` 곱셈 오류가 난다. null을 거부하거나 기본값을 쓴다.
     - (P2, 추정) `cover: page` 바로 뒤에 `landscape: true` 표가 오면 쪽 나누기와 다음 쪽 구역 나누기가 연달아 들어가 빈 세로 쪽이 생길 수 있다. 표지 쪽 나누기를 구역 전환으로 대신한다.
     - (P3, 재현됨) `page_number`의 캐리지 리턴(`\r`)을 막지 않아 바닥글에 실제 줄바꿈이 들어간다. `\n`과 함께 거부한다.
     - (P3, 재현됨) `label_color: ""`를 거부한다. 문서상 빈 값은 기본 회색이므로 허용한다.
     - 이상 없음으로 확인된 항목: `style`이 없을 때 모든 샘플이 바이트 단위로 같음, 로고 경로 해석과 우선순위, 로고 누락 진단, 가로·세로 구역의 머리글·바닥글, OOXML 순서.
     - 참고: 로고가 임의 로컬 파일을 싣는 위험은 기존 이미지 정책과 같다(로드맵 E1에서 함께 다룬다).
2. **#21 CI는 수정 전 커밋에서 8/8 통과했다.** 수정 커밋을 push한 뒤 다시 확인한다.
3. **5절을 구현했다.** 아래 설계를 따랐고, 구현하며 정한 내용은 다음과 같다.
   - 모듈은 `converted_md_cleaner.py`(`deep_md_cleaner.py`처럼 별도 모듈)이고 `md-format --converted-term-sheet`로 실행한다. 이 모드는 Deep Research 정리를 대신하며 `--deepresearch-cleaner`와 함께 쓸 수 없다.
   - 한 단락에 표지 줄 여러 개가 빈 줄 없이 붙어 있으면 줄 단위로 분류한다. 분류되는 줄이 하나도 없는 80자 이상 단락만 통째로 `disclaimer`가 된다. 80자 이상 줄은 굵어도 제목이 아니라 고지문으로 본다.
   - 줄 끝 강제 줄바꿈(`\`, `<br>`)은 분류 전에 떼고, 고지문 안에서는 줄바꿈으로 남긴다.
   - 기존 frontmatter는 줄 그대로 두고 새 키만 닫는 `---` 앞에 붙인다. 이미 있는 키에 해당하는 표지 줄은 본문에 남기고 보고한다.
   - 장 제목이 하나도 없으면 표지를 옮기지 않고 그렇게 보고한다.
   - Codex 리뷰(11건) 반영: 최상위 블록만 바꾼다(들여쓴 코드·목록 연속·인용·중첩 HTML 표는 그대로). `#` 제목은 빈 줄 없이도 앞 단락을 끝낸다. 셀 밖 글자가 있는 HTML 표는 띠 표로 보지 않는다. frontmatter는 파서와 같게 `---`로 닫고(`...`는 바꾸고 보고) 키를 대소문자 구분 없이 비교하며, 덧붙일 수 없는 흐름 형식은 블록 YAML로 다시 쓰고 보고한다. 이스케이프된 `\<br>`은 줄바꿈이 아니다. 여러 줄 변경은 줄 범위로 보고한다. `--check`·DeepResearch 옵션과 함께 쓰면 거부한다.
   - Codex 재리뷰(6건) 반영: 표지의 인용·글머리 목록·들여쓴 이어짐이 있는 번호 항목은 통째로 남긴다(한 줄짜리 날짜·번호 줄은 계속 분류). 들여쓴 코드 블록은 들여쓰기가 끝나는 줄에서 끝난다. 추가할 키가 없어도 흐름 형식 frontmatter는 블록 YAML로 바꾼다. 들여쓴 2단계 이상 제목도 표지 범위를 끝낸다. HTML 표 깊이는 주석과 따옴표 속성을 건너뛰고 센다. 1행 HTML 표는 셀 글자에 Markdown·HTML 문자가 있거나 주석이 있으면 표로 둔다.
   - Codex 3차 리뷰(3건) 반영: HTML 글자는 실제 태그만 지우고 인라인 태그는 붙여 읽는다(`1<span>00</span>` → `100`, `a < b`는 글자). 띠 제목 글자에 인라인 문법 문자(`* _ $ ^ ~` 등)가 있으면 셀을 이어 붙일 때 새 문법이 생길 수 있으므로 표로 두고 보고한다. 인용·글머리 줄은 빈 줄 없이도 앞 단락을 끊는다.
   - Codex 4차 확인(2건) 반영: 1행 HTML 표는 셀에 `<p>` 하나와 서식 태그(굵게·기울임·밑줄·span)만 있을 때만 제목으로 바꾸고, `<br>`·`<sup>`·링크 등이 있으면 표로 두고 사유를 보고한다. 인용·글머리 줄은 0열일 때만 앞 단락을 끊고, 들여쓴 목록·인용 줄이 든 블록은 통째로 둔다. 표지 블록 안의 들여쓴 줄은 따로 옮기지 않는다.
   - 그대로 둔 한 줄짜리 번호 단락(굵지 않고 뒤에 표가 없음)도 장 제목인지 확인하도록 보고한다. 가상 예시에서 이런 줄은 뒤 목록과 이어져 번호가 매겨졌다.

## 3. 5절 설계: 변환본 정리 모드(opt-in)

HWP나 Word를 외부 변환기로 바꾼 Markdown은 다음과 같은 모양이 된다.

- 장 제목이 굵은 번호 문장이다(`**1. 본건 개요**`). 굵지 않은 번호 문장 뒤에 표가 오기도 한다.
- 표지 내용이 본문 맨 앞에 섞여 있다. 대외비 표시가 두 번 나오고, 제목 줄, 날짜, 로고 이미지, 고지문 단락, 본문 쪽 머리글 문구가 이어진다.
- 1행짜리 "별첨" 띠 표가 있다(`| 별첨 | | 상환스케줄 |`).

AGENTS 규칙상 파서의 기본 동작은 짧은 번호 문장을 제목으로 올리면 안 된다. 따라서 이 정리는 **사용자가 명시적으로 실행하는 MD→MD 단계**로만 제공한다.

- **위치.** `md_formatter.py`의 새 옵션이다(예: `--converted-term-sheet`). 기본 동작과 기존 옵션은 바꾸지 않는다.
- **장 제목 승격.** 한 줄짜리 단락이 `^\**\d{1,2}\.\s+.{1,40}\**$` 형태이고, 굵게 쓰였거나 바로 다음 블록이 표(파이프 또는 HTML)일 때만 `## …`로 바꾼다.
- **띠 표.** 머리행만 있고 본문 행이 없는 표는 빈 칸을 뺀 셀을 ` | `로 이어 `## …` 제목으로 바꾼다.
- **표지 → frontmatter.** 첫 장 제목 앞의 블록만 대상으로 한다.
  - `Strictly Confidential` 같은 대외비 줄 → `confidential_label`. 중복 줄은 없앤다.
  - 맨 앞의 굵은 줄 → 첫 줄은 `title`, 나머지는 `subtitle`.
  - 날짜 형식 줄 → `date`.
  - 긴 고지문 단락 → `disclaimer`.
  - 표지 이미지 → 본문에서 빼고, house `style.logo`로 옮기라고 보고한다(로고 파일은 기관 자산이라 저장소에 두지 않는다).
  - 판단이 어려운 줄(예: 본문 쪽 머리글 문구)은 **그대로 두고 보고만** 한다.
- **frontmatter.** `profile: term-sheet`를 쓴다. `prepared_by`는 추론하지 않으며, 없으면 house나 frontmatter에 넣으라고 보고한다.
- **보고.** 옮기거나 바꾸거나 뺀 항목을 한 줄씩 출력한다. 내용을 조용히 버리지 않는다.
- **테스트.** 가상 이름으로 쓴 변환기 모양 입력으로만 테스트한다. 실제 문서는 저장소 밖(`tmp/`)에서 수동 확인에만 쓴다.
  - 장 제목 승격이 켜진 경우와 꺼진 경우(기본 동작 불변).
  - 띠 표 변환.
  - 표지 항목 추출.
  - 판단 불가 줄 보존.
  - 정리 결과를 `--strict`로 렌더링했을 때 경고가 없을 것.

## 4. 참고

- 두 번째 실제 텀싯(변환 Markdown)은 이 PC의 `tmp/`에만 있다. 다른 PC에는 없으므로 5절 수동 확인은 원본이 있는 곳에서 한다.
- 이 PC의 임시 폴더에 4절 리뷰용 분리 체크아웃이 남아 있을 수 있다. `git worktree prune`으로 정리한다.
