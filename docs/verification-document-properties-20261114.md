## 1. 조사에서 확인한 사실

로드맵 본문의 E8 절은 DOCPROPERTY 필드 문법과 워터마크 구조를 Microsoft 1차 문서가 아닌 오픈소스 구현에서 보았다고 스스로 "미검증"으로 적었다. 그래서 이 기기의 Word로 문서를 직접 만들어 저장하고, 그 XML과 Word의 동작을 재서 기준으로 삼았다. 시험 문서는 모두 가상이며 저장소 밖에 있다.

**Word가 저장하는 구조.**

- 사용자 지정 속성: `docProps/custom.xml`의 `<property fmtid="{D5CDD505-2E9C-101B-9397-08002B2CF9AE}" pid="2부터" name="Version"><vt:lpwstr>v1.0</vt:lpwstr></property>`. 엔진이 서명용으로 이미 쓰던 형식과 같다.
- 필드: 필드 코드 ` DOCPROPERTY Version \* MERGEFORMAT `와 결과 글자(캐시)를 함께 저장한다. 한글이나 빈칸이 든 속성 이름은 따옴표로 감싸야 한다. 없는 속성을 가리키면 갱신 뒤 `오류! 알려지지 않은 문서 속성 이름입니다.`가 찍힌다.
- 워터마크: 머리글 안의 VML 워드아트 도형이다. `v:shape`의 `id`가 `PowerPlusWaterMarkObject숫자`이고, 315도 회전, 은색 50% 투명, 여백 기준 가운데, 글 뒤에 놓인다. 갤러리(초안 1 등)로 넣으면 `Watermarks` 콘텐츠 컨트롤로 한 번 더 감싸고, 사용자 지정 워터마크 대화상자로 넣으면 감싸지 않는다.

**Word의 동작.**

| 확인한 것 | 결과 |
|---|---|
| 문서를 열 때 | 대화상자가 뜨지 않고, 머리글은 저장된 캐시 글자 그대로 보인다. 엔진이 켜 두는 `w:updateFields`가 있어도 머리글 필드는 열 때 갱신되지 않았다. |
| 속성을 바꾼 뒤 본문에서 Ctrl+A → F9 | 목차는 갱신되지만 **머리글은 그대로**다(실제 키 입력으로 확인). |
| 머리글을 두 번 눌러 Ctrl+A → F9 | **그 구역의** 머리글만 갱신된다. 엔진은 구역마다 머리글을 따로 만드므로, 가로 표가 있어 구역이 셋인 문서에서는 F9를 누른 구역만 바뀐다. |
| Ctrl+P(인쇄 화면)·인쇄 미리보기 | **모든 구역**의 머리글이 갱신된다. |
| PDF로 저장 | 화면의 머리글이 옛 값이어도 PDF에는 새 값이 찍힌다. |
| 저장하고 다시 열기 | 갱신되지 않는다. |
| 워터마크 갤러리가 넣는 범위 | **커서가 있는 쪽의 머리글 하나**에만 넣는다. 엔진 문서에 넣으면 1구역에만 생기고 가로 표 쪽에는 생기지 않는다. |
| 워터마크 제거가 지우는 것 | `id`가 `PowerPlusWaterMarkObject`로 시작하는 도형을 **모든 구역의 모든 머리글에서** 지운다(커서가 어느 구역에 있어도 같다). 이름이 다르면 지우지 않는다. 이름이 달라도 `Watermarks` 콘텐츠 컨트롤 안에 있으면 커서가 있는 구역 것만 지운다. |

**로드맵의 서술과 달랐던 것.**

1. 로드맵은 "Word는 워터마크를 모든 머리글의 VML 도형으로 저장한다"고 적었다. 갤러리는 커서가 있는 머리글 하나에만 넣는다. 그래서 엔진이 직접 모든 머리글에 넣어야 여러 구역 문서가 빠짐없이 표시된다.
2. 로드맵은 "파일 속성에서 버전을 바꾸고 F9만 누르면 된다"고 적었다. 본문의 F9로는 머리글이 바뀌지 않는다. 머리글 안에서 F9를 누르거나(그 구역만), Ctrl+P·인쇄 미리보기를 열어야(모든 구역) 바뀐다.
3. 로드맵은 `status: draft`가 워터마크와 함께 **머리글 DRAFT 글자 도장**도 켜자고 했다. 글자 도장은 Word의 워터마크 제거로 지워지지 않아 최종본으로 바꿀 때 남으므로 넣지 않았다.
4. 로드맵에 없던 것: 엔진 문서의 파일 정보가 python-docx 서식 파일의 값(만든 이 `python-docx`, 메모 `generated by python-docx`, 날짜 2013-12-23, 제목 없음)으로 나왔다. 엔진 문서는 Word에서 호환성 모드로 열린다(이번에 바꾸지 않음).

## 3. 바꾼 것과 이유

**커밋 1 `4ae2377` — 버전 속성과 필드.** `version`이 있으면 사용자 지정 속성 `Version`을 쓴다. 머리글에는 회사명 뒤에 ` | `와 버전을 쓰되, 버전 글자를 ` DOCPROPERTY Version \* MERGEFORMAT ` 필드의 결과(캐시)로 만든다. 열자마자 바른 값이 보이고, 속성을 바꾸면 F9로 따라온다. 필드의 각 부분은 결과 글자와 같은 서식을 가져, 갱신 뒤에도 모양이 같다. 공문은 버전을 보여 주지 않지만 속성은 쓴다(파일 속성에서는 보인다). 텀싯은 바닥글 `"{부제} {버전}"`을 그대로 보여 주고 버전 부분만 같은 필드로 바꿨다. 버전을 적지 않은 문서는 속성도 필드도 생기지 않는다.

**커밋 2 `9a7d511` — DRAFT 워터마크.** `status: draft`이면 모든 구역의 모든 머리글(첫 쪽·짝수 머리글을 쓰는 문서라면 그것까지)에 Word의 사용자 지정 워터마크와 같은 VML 도형을 하나씩 넣는다. 도형 `id`는 `PowerPlusWaterMarkObject1`, `2`, …로 문서 안에서 겹치지 않는다. 표지도 같은 머리글을 쓰므로 표지에도 찍힌다. `status: final`이거나 `status`가 없으면 넣지 않는다. 그 밖의 값(`Draft`, `DRAFT`, `초안`, 빈 값 등)은 strict 여부와 상관없이 거부한다. 오타로 초안 표시가 빠지는 것을 막기 위해서다. 새 QA 샘플은 표지, 가로 표 구역(3구역), `version`, `status: draft`를 함께 쓴다.

**커밋 3 `469db73` — 파일 정보.** 만든 이와 메모를 비우고(만든 이를 추측해 넣지 않는다. 다음에 저장하는 사람은 Word가 기록한다), 만든 날짜와 수정한 날짜를 변환한 시각(UTC, 초 단위)으로, 제목을 문서 제목으로 쓴다. 프로필의 대체 제목(`Document`, `IB Report`)은 문서가 정한 제목이 아니므로 파일 제목에 쓰지 않는다. 텀싯의 주제(`Term Sheet` 등) 처리는 그대로다.

## 4. 바꾸지 않은 것과 이유

- **따옴표 없는 숫자 버전·여러 줄 버전의 거부**(요구사항 초안 7절): 넣지 않았다. `AGENTS.md`는 "숫자·날짜·글자 목록 같은 메타데이터 값은 지금처럼 렌더링되어야 한다"고 정하고, 기존 테스트 `tests/test_document_rejections.py::test_existing_metadata_scalar_coercions_render`가 strict 모드에서 `version: 2`가 렌더링되는 것을 고정한다. 그래서 `version`은 지금까지의 메타데이터 처리 그대로 글자로 바꿔 쓴다. `version: 1.10`은 YAML이 숫자 `1.1`로 읽으므로 `1.1`로 나온다. 안내 문서에 "버전은 따옴표로 감싼다"고 적었다. 이 차이는 구현 중에 드러났다.
- **머리글 DRAFT 글자 도장**: 1절 3번의 이유로 넣지 않았다.
- **구역 머리글 묶기**: 소유자 결정 4.
- **거래명·분류·기준일 속성, 핵심 속성의 `상태`**: 소유자 결정 5. `상태`(contentStatus)는 쓰는 곳을 확인하지 않았다.
- **`--draft`/`--final` CLI 옵션**: 요청이 없다.
- **호환성 모드, `w:updateFields`**: 이번 범위가 아니다. `w:updateFields`는 머리글 필드를 열 때 갱신하지 않았지만 다른 필드(쪽 번호)를 위해 그대로 둔다.
- **플러그인 스킬 문서**(`skills/`, `.agents/skills/`): 바꾸지 않았다. 텀싯 예시의 `version` 쓰는 법은 같다.

## 5. 완료 기준 확인 (이 기기의 Word)

바뀐 엔진(커밋 `469db73`)으로 새 QA 샘플 `samples/qa/draft-version.md`를 만들었다. 표지가 있고 가로 표 때문에 구역이 셋인 6쪽 문서다. 같은 결과를 저장소 밖의 사본으로 시험했다.

**(가) 버전 갱신.** 자동 조작으로 띄운 Word(이 검증만을 위한 인스턴스)에서 파일을 열었다. 대화상자는 뜨지 않았고 머리글은 `예시금융 | v0.3`이었다. **파일 > 정보 > 속성 > 고급 속성 > 사용자 지정**에서 `Version`을 `v0.4`로 바꿨다(실제 화면 조작). 요약 탭에는 제목 `가상 회사채 발행 검토`가 있고 만든 이·메모는 비어 있었다(커밋 3).

| 동작 | 구역 1·2·3 머리글 |
|---|---|
| 속성 변경 직후 | v0.3, v0.3, v0.3 |
| 1쪽 머리글을 두 번 눌러 Ctrl+A → F9(실제 키) | v0.4, v0.3, v0.3 |
| 이어서 Ctrl+P(실제 키), 인쇄 미리보기 4쪽(가로 구역) 확인 후 Esc | v0.4, v0.4, v0.4 |

인쇄 미리보기의 4쪽(가로 구역) 머리글에 `v0.4`가 찍힌 것을 화면으로 확인했다. 조사 단계에서 본문 Ctrl+A → F9로는 머리글이 바뀌지 않는 것과, PDF 저장에는 새 값이 찍히는 것을 확인했다(1절).

**(나) 워터마크 제거.** 같은 Word에서 새 사본을 열어 커서를 문서 맨 앞에 두고 **디자인 > 워터마크 > 워터마크 제거**를 눌렀다(실제 화면 조작). 표지(1쪽)부터 가로 구역(4쪽)과 마지막 쪽까지 DRAFT가 모두 사라졌고, 남은 머리글 도형은 0개였다. 자동 조작으로 같은 명령(`WatermarkRemove`)을 실행한 경우도 확인했다.

| 문서 | 제거 전 머리글 | 제거 후 |
|---|---|---|
| QA 샘플(ib-report, 표지, 3구역) — 실제 화면 조작 | 3개 구역 모두 | 0 |
| 최소 텀싯 + `status: draft` | 1구역 | 0 |
| 공문 샘플 + `status: draft` | 1구역 | 0 |
| 가로 표 QA 샘플(ib-memo, 3구역) + `status: draft` | 3개 구역 모두 | 0 |

워터마크가 표와 겹치는 쪽에서도 숫자는 읽힌다(6절의 쪽 이미지). 조사 단계에서 PDF로 저장한 문서에도 워터마크가 찍히는 것을 확인했다.

## 11. 되돌리는 방법

세 커밋은 순서대로 쌓였고, 각 커밋 시점에서 7절의 검사를 모두 통과했다. 커밋 3만 되돌리면 커밋 2의 상태, 커밋 2·3을 되돌리면 커밋 1의 상태가 된다. 이미 만든 문서는 필드에 캐시 글자가 있고 워터마크는 Word에서 지울 수 있으므로 그대로 쓸 수 있다.
