# 표·그림 번호와 상호 참조 검증 (2026-11-14)

로드맵 E5(표·그림 캡션 번호와 본문 상호 참조)의 구현과 검증 기록이다. 확인한 것과 확인하지 않은 것을 나누어 적는다. 구조 검사 통과는 시각 검토 통과를 뜻하지 않는다.

## 환경

Windows 11(10.0.26300), Python 3.12.12, uv 0.11.28, ruff 0.15.0, mypy 1.14.1, pytest 9.0.2, python-docx 1.2.0, lxml 6.0.2, Microsoft Word 16.0(빌드 16.0.20527, 한국어 화면). 기준 커밋은 `84cde43`이고, 그 상태의 전체 테스트는 **2666 passed, 5 skipped, 1 xfailed**였다.

## 요약

- 표 사양에 `id: tbl-…`를 준 표와 그림 줄 끝에 `{#fig-…}`를 단 그림에만 `표 1. 제목`, `그림 1. 설명` 번호가 붙는다. 번호는 Word가 "캡션 삽입"으로 만드는 것과 같은 `SEQ` 필드다.
- 본문의 `@tbl-…`, `@fig-…`는 Word 상호 참조(`REF` 필드)가 되어 `표 1`, `그림 1`로 보이고, 누르면 그 표로 간다.
- 목표는 풀리는 참조와 번호 붙는 캡션 말고는 산출물이 바뀌지 않는 것이다(P1). 3차 독립 검토 전까지는 이 목표가 깨져 있었다. 엔진이 이스케이프 표시로 쓰던 사용자 정의 영역 문자 U+E010·U+E011이 입력에 있으면 코드 안에서도 `@`·`$`로 바뀌었다([22], 아래 "3차 독립 검토"). 고친 뒤 확인한 범위는 이렇다. 스냅숏 300개 가운데 기준선 `84cde43`에 있던 279개는 바뀌지 않았고, 나머지 21개는 E5 새 샘플 `samples/qa/captions.md`의 스냅숏이다. 기존 샘플 13개의 Word 쪽 이미지 32장도 픽셀 단위로 같다(구현 단계에서 확인). 참조가 아닌 글자와 풀리지 않는 참조 54가지 입력은 본문 XML이 `84cde43`과 같다. 고정 시드로 임의 조각을 이어 만든 문서 6개(블록 300개)에서는 참조 범위를 켠 출력, 끈 출력, 사용자 정의 영역 문자를 보통 기호로 바꿔 넣은 출력이 같다. 모든 입력에 대한 증명은 아니다.
- 커밋: `59d4541`(캡션 번호), `5e6c73c`(본문 상호 참조와 `docx-audit` 검사), `bfdee0a`(사용 안내와 이 문서), `cbe2b26`(로드맵 기록). 독립 검토 뒤의 수정 커밋은 아래 "독립 검토"와 "독립 재검토" 절에 있다.

## 조사에서 확인한 사실

이 기기의 Word로 직접 확인했다. 확인할 때는 엔진 산출물의 사본에 Word가 만든 캡션과 참조를 넣거나, 후보 구조를 붙여 보았다.

1. **미리 계산한 값(캐시)은 필수다.** 문서에 "열 때 필드 갱신" 설정(`w:updateFields`)이 있어도 Word는 열 때와 인쇄 미리보기 때 `SEQ`와 `REF`를 다시 계산하지 않는다. 일부러 틀린 값 `표 9`를 넣으면 F9를 누르기 전까지 그대로 보였다. 그래서 엔진은 번호와 참조 글자를 미리 정확히 계산해 적는다.
2. **한국어 Word의 기본 캡션 레이블은 `Figure`, `표`, `수식`이다.** `그림`은 기본 레이블이 아니다. `그림` 번호를 Word에서 이어 붙이려면 사용자가 `그림` 레이블을 한 번 만들어야 한다. `Table` 레이블도 한국어 Word에는 없다. Word의 상호 참조 목록은 레이블 등록과 관계없이 `SEQ` 이름으로 캡션을 찾았다(`그림` 목록에 엔진 그림이 나옴).
3. **서식 스위치가 필요하다.** Word가 직접 넣는 상호 참조(`REF _Ref… \h`)에는 서식 스위치가 없다. 이 상태에서 F9를 누르면 캡션의 서식(작은 글씨, 기울임, 굵은 남색)이 본문 참조에 복사된다. `\* CHARFORMAT`을 붙이면 본문 서식이 유지된다.
4. **장 번호는 맞지 않는다.** Word의 장 번호 캡션(`표 2-1`)은 제목에 Word 자동 번호가 있어야 한다. 이 엔진은 `## 1. 개요`처럼 번호를 글자로 쓰므로 F9 뒤 `표 0-1`로 깨졌다.
5. 대상 캡션을 지우고 F9를 누르면 참조는 `오류! 참조 원본을 찾을 수 없습니다.`가 된다.

## 더한 것과 이유

**캡션 번호(`59d4541`).** 번호를 붙일 표에는 표 사양에 `id`를, 그림에는 이미지 파일 줄 끝에 `{#fig-…}`를 단다. 캡션 줄은 `표 ` 글자, `SEQ 표 \* ARABIC` 필드(값 포함), `. `, 제목 순서다. 레이블과 번호 `표 1`을 숨은 북마크 `_Ref_tbl_results`(ID의 하이픈을 밑줄로)가 감싼다. 이 북마크가 본문 참조의 대상이다. 북마크 이름과 번호는 입력이 같으면 항상 같다. 캡션 서식(위치, 글꼴, 단위 줄, 출처, 주석)은 그대로이고, 텀싯은 같은 줄 왼쪽 제목 앞에 번호가 붙고 오른쪽 `(단위 : …)`는 그대로다.

**본문 상호 참조(`5e6c73c`).** `@tbl-results`는 `REF _Ref_tbl_results \h \* CHARFORMAT` 필드가 되고 값 `표 1`을 담는다. 문단, 목록, 인용, 제목, 표 칸, 표 제목·단위·출처·주석에서 쓸 수 있고, 굵게·기울임 안에서는 그 서식을 따른다. ID가 영문이므로 한글 조사를 바로 붙일 수 있다(`@tbl-results에서`).

**참조로 읽는 규칙(독립 재검토 뒤 확정).** 모든 자리(문단, 인용, 목록, 제목, 목차 미리보기, 파이프 표 칸, HTML 표 칸, 표 제목·단위·출처·주석, 문서 제목·부제와 문서에 나오는 다른 frontmatter 값, 그림 설명, 각주)가 같은 함수 하나(`TextParser._reference_candidates`)로 참조를 찾는다. 이 함수는 run 목록 전체의 보이는 글자를 한 번에 읽는다.

- `@` 바로 앞에 보이는 글자가 줄 처음, 공백, 여는 괄호나 따옴표(`(`, `[`, `{`, `<`, `"`, `'`, `「`, `『` 등)일 때만 참조 후보다. 글자·숫자·`+`·`.`·`_`·`-` 뒤의 `@`(이메일 `user+@tbl-x.example`, `doc-team@tbl-example.com`)는 아니다. 굵게·기울임·색 지정은 건너뛰고 보며, 내용이 빈 색 지정은 없는 것으로 본다(`x**@tbl-a**y`, `x<span …></span>@tbl-a`는 `x` 뒤라서 아니다).
- `@` 뒤 `tbl-`/`fig-`와 그 뒤의 ID 글자(영문·숫자·`-`·`_`)를 통째로 읽는다. 모양이 틀리면(`@tbl-a-`, `@tbl-a--`, `@tbl-`, `@fig-`, `@tbl-Results`) 앞부분만 참조로 쓰지 않고 오류로 보고한다. 서식이 ID를 가르면(`@tbl-a**b**`, `@tbl-a<span …>b</span>`, 제목의 `## @tbl-**a**`) 오류로 보고한다. 제목은 렌더러가 `**`를 지우고 그리지만 판정은 `**`가 있는 원문으로 한다.
- ID 뒤에 `.`과 영문·숫자가 이어지면(`@tbl-x.example`) 도메인으로 보고 참조가 아니다. 보이는 ID 전체를 읽은 뒤 판정하므로 `@tbl-a**b**.com`도 도메인이다.
- 코드 스팬·코드 블록, 수식 `$…$`(수식을 그리지 않는 표 칸·인용에서도), 링크 주소, 역슬래시로 막은 `\@`, 조건 변수가 넣은 값은 어디서나 참조가 아니다. 이스케이프한 `@`·`$`는 읽기가 끝날 때까지 표시 문자로 남는다. 파싱 때 이스케이프를 미리 푸는 인용과 번호 제목은 이스케이프한 `@`를 따로 표시해 둔다.
- 참조로 읽지 않은 글자와 풀리지 않는 참조는 run을 나누지도 글자를 바꾸지도 않는다. 파서는 풀리는 참조가 있는 run만 그 참조 둘레에서 나누고, 나머지는 run을 건드리지 않고 진단만 낸다. 무엇이 풀리는지는 `ReferenceScope`가 정한다. `@tbl-`/`@fig-`가 든 문서는 풀리는 것이 없는 범위에서 한 번 파싱해 번호 붙는 표·그림을 찾고, 있으면 그 ID로 한 번 더 파싱한다. 렌더러는 자기 번호의 범위에서 그린다.

**거부.** strict 모드는 저장하지 않고, 기본 모드는 글자를 원문 그대로 두고 경고를 남긴다.

| 입력 | strict | 기본 모드 |
|---|---|---|
| 없는 ID를 가리키는 참조, 모양이 틀린 참조(`@tbl-a-`, `@tbl-`, `@tbl-Results`), 서식이 가른 ID | 거부 | 원문 그대로, 경고 |
| 필드를 넣을 수 없는 자리의 참조(그림 설명·인라인 그림 설명, 각주, 링크 글자, 문서 제목·부제와 문서에 나오는 다른 frontmatter 값 — 아래 목록) | 거부 | 원문 그대로(텀싯 제목·부제·날짜·작성 기관 포함), 경고 |
| 번호를 붙일 수 없는 `{#…}`(모양 오류, 설명 없음, Base64 그림, 문단·목록·표 칸 안의 그림), 같은 그림 ID 두 번 | 거부 | 지금처럼 글자로, 중복은 번호만 붙고 북마크 없음, 경고 |
| 표 사양 `id` 오류(모양, 중복, 제목 없음) | 거부 | 거부(다른 표 사양 오류와 같음) |
| 칸이 없어 그려지지 않는 표의 `id` | 거부 | 저장, 경고, 그 표에 번호 없음(그 표를 가리키는 참조는 대상 없음) |
| 실제로 쓴 캡션 번호가 미리 정한 번호와 다름(기본 모드에서 표 하나가 그려지지 못한 경우 등) | 거부 | 저장, 경고 |

**검사하는 frontmatter 값.** 문서 제목·부제는 언제나, 날짜는 `plain`을 뺀 모든 프로파일에서 파서가 조건 변수를 넣기 전 원문으로 검사한다. 나머지 값은 렌더러가 그 값을 보여 주는 자리에서만 검사한다(`IBDocumentRenderer._check_metadata_references`).

| 자리 | 키 |
|---|---|
| IB 표지(`cover`) | `sector`, `ticker`, `subject_company`(비었으면 `company`), `analyst`, `recipient`, `analysis_period`, `analysis_basis` |
| 제목 블록(`render_office_opening`) | `sender.department`, `analyst`, `meeting_time`, `location`, `attendees`. 공문은 `sender.organization`, `recipients`, `cc` |
| 공문 끝 | `attachments`, `sender.signatory`(없으면 `sender.organization`), `document_no`, `sender.department`, `sender.contact` |
| 머리글(공문·텀싯 제외) | `sender.organization`(없으면 `company`), `version`(E8, 회사명 뒤) |
| 면책 쪽 | `company` |
| 텀싯 | `version`(바닥글), 하우스·frontmatter의 `prepared_by`, `disclaimer`, 기밀 표시 문구 |

IB 프로파일의 파일·스트림 파서가 본문 앞쪽의 `**작성자:** 값` 같은 문단에서 읽은 값(`analyst`, `company`, `sector`, `date`, `recipient`, `analysis_period`, `analysis_basis`)과 제목에서 읽은 `subject_company`는 `InferredText`다. 그 문단은 본문으로 이미 판정됐으므로, 렌더러는 그 값을 보여 주는 자리에서 글자를 다시 읽지 않고 그 문단에서 풀린 참조만 보고한다(날짜 포함). 조건 변수 값, 이스케이프한 `@`, 코드는 참조가 아니다.

값은 보이는 모양대로 읽는다(일반 글자, 텀싯 문구는 인라인 Markdown). `report_type`은 대문자로 나오므로 참조가 될 수 없다. 텀싯의 제목·부제·날짜·작성 기관·면책 문구는 참조 범위 밖에서 그려 필드가 생기지 않는다. 테스트 `test_metadata_references_are_reported_exactly_where_they_are_shown`은 7개 프로파일마다 모든 키에 서로 다른 참조를 넣고, 진단된 키와 산출물에 나온 키가 같은지(부제는 언제나 진단) 확인한다.

**`docx-audit` 검사.** 대상 북마크가 없는 `REF`/`PAGEREF` 필드는 issue로, 값이 대상과 다른 참조나 문서 순서대로 1, 2, 3…이 아닌 번호는 warning("Word에서 전체 선택 후 F9")으로 보고한다. 따옴표로 감싼 북마크 이름과 다른 필드 안에 든 필드(`w:fldSimple` 안의 복합 필드 포함)도 읽는다. 번호 순서는 스위치가 없거나 `\* ARABIC`만 있는 `SEQ` 열만 판정한다. **본문만 검사한다(머리글·바닥글·각주는 검사하지 않는다).** 엔진은 strict 저장 전에 같은 검사를 거친다.

**구조.** 새 모델 형식은 기존 클래스의 하위 클래스다(`NumberedTable`, `Figure`, `CaptionNumber`, `CrossReference`, `MarkedHeading`, `MarkedBlockquote`). 기존 클래스에 필드를 더하면 모든 문서의 모델 스냅숏이 바뀌기 때문이다. 번호는 한 번 그릴 때 `IBDocumentRenderer._caption_numbers`에서 한 번만 매기고, 파서가 풀리는 ID를 얻는 목록(`numbered_items`)과 같은 목록을 쓴다. 그려지는지 판정은 렌더러와 같은 함수(`table_is_drawn`)를 쓴다. 문서를 만드는 경로는 하나다. 새 모듈은 없다.

| 차트·도식·표 칸 안 그림·Base64 그림 번호 | 이번 범위 밖. Base64 그림은 파일 이름이 없어 ID를 달 줄을 정할 수 없다 |

## 요구사항 초안과 달라진 점

1. **ID에 밑줄을 쓸 수 없다.** 초안은 밑줄을 허용했다. 북마크 이름은 하이픈을 밑줄로 바꾸므로 `tbl-a-b`와 `tbl-a_b`가 같은 북마크가 된다. 그래서 영문 소문자·숫자와 하이픈만 허용한다(35자 이하).
2. **표 사양 `id`의 모양 오류·중복·제목 없음은 두 모드 모두 거부한다.** 초안은 strict만 거부한다고 했다. 표 사양의 다른 오류가 이미 두 모드 모두 거부하므로 그 규칙을 따랐다. 칸이 없어 그려지지 않는 표의 `id`만은 그리는 단계에서 알 수 있어 strict에서 거부하고 기본 모드에서는 경고와 함께 번호를 주지 않는다(독립 재검토 [20]에서 문서를 동작에 맞춤).
3. **표 제목·단위·출처·주석과 제목에서도 참조를 쓸 수 있다.** 초안은 YAML 글자 안의 참조를 거부하려 했다. 이 글자는 본문과 같은 방식으로 Word 문단이 되므로 필드를 넣을 수 있다.
4. **각주 안의 참조는 글자로 남고 거부된다.** 각주는 지금 서식 없는 글자로만 쓰여 필드를 넣을 수 없다.
5. **Base64 그림에는 ID를 달 수 없다.**
6. **참조의 경계 규칙을 문법으로 정했다(독립 검토 뒤).** 초안은 "앞에 글자가 붙은 `@`는 참조가 아니다"까지만 정했다. 지금은 앞 글자(줄 처음·공백·여는 괄호나 따옴표), ID 전체 검사, 도메인 모양 제외를 정했고, 그 결과 strict가 풀리지 않는 `@tbl-…`/`@fig-…`를 모두 거부한다.
7. **번호를 붙일 수 없는 `{#…}`의 진단은 렌더러가 한다.** 그림 줄 앞에 문단이 있으면 그 줄이 문단에 흡수되어 파서 검사를 건너뛰었기 때문이다. 이제 그림 뒤 `{#…}`는 어디에 있든 같은 판정으로 보고한다.

## 하지 않은 검증

- **5차 확인의 독립성.** 5차는 소유자 지시로 조율 세션이 직접 검토하고 고쳤다. 고친 내용을 다른 모델이 다시 검토하지는 않았다.
- **5차 수정 뒤 Word 확인.** 5차 수정은 진단만 더하고 기본 모드 산출물을 바꾸지 않아 Word에서 다시 열어 보지 않았다.

- **Word 상호 참조 대화상자의 화면.** 화면 조작을 하지 않았다. 대화상자가 쓰는 목록(`GetCrossReferenceItems`)으로 `표`, `그림` 목록에 엔진 캡션이 나오는 것만 확인했다.
- **Word에서 `그림` 레이블을 만들어 그림 캡션을 이어 넣는 경우.** 이번 단계에서는 Word에 레이블을 추가하지 않았다. 1단계 조사에서 같은 구조를 확인했다.
- **다른 Word 버전, macOS Word, LibreOffice, 한컴오피스.** 확인하지 않았다.
- **실제 보고서.** 가상 샘플만 썼다.
- **frontmatter 값 검사의 옵션별 차이.** 날짜는 `plain`을 뺀 모든 프로파일에서 검사한다. 표지도 제목도 없는 `ib-report`처럼 날짜가 나오지 않는 드문 조합에서도 검사한다. 나머지 키 목록은 기본 옵션의 7개 프로파일로만 산출물과 맞췄다.
- **머리글·바닥글·각주의 필드.** `docx-audit`는 본문만 검사한다.
- **재검토 뒤 기존 샘플의 쪽 이미지.** 다시 그리지 않았다. 기존 스냅숏 279개가 그대로이고, 풀리지 않는 참조 39가지 입력의 `document.xml`이 `84cde43`과 같다는 것으로 갈음했다.
- **표시 문자가 바닥나는 경우.** 15·16면 사용자 정의 영역 문자를 모두 담은 글(약 13만 자)은 만들지 않았다. 표시 후보를 두 글자로 줄인 테스트로만 진단과 범위 밖 처리를 확인했다.
- **임의 P1 테스트의 범위.** 문서 6개, 블록 300개다. 모든 입력에 대한 증명이 아니다. 텀싯·공문 프로파일과 표 사양이 있는 문서는 이 테스트에 들어 있지 않다.
- **3차 수정 뒤 기존 샘플의 쪽 이미지.** 다시 그리지 않았다. 스냅숏 300개가 그대로이고 54가지 입력의 `document.xml`이 `84cde43`과 같다는 것으로 갈음했다.
- **쪽 이미지의 글자 굵기.** 표 12개 문서의 첫 문단에서 굵게 지정하지 않은 앞부분이 쪽 이미지에서 조금 진하게 보였다. Word가 저장한 사본의 글자 속성은 굵게가 아니어서 이미지로 바꿀 때의 차이로 보고 넘겼다.
