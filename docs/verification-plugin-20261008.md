# 공용 문서 플러그인 검증 — 2026-10-08

Claude Code와 Codex가 공통 `setup`·`ib-document` 스킬 및 기존 Markdown → Word 엔진을 사용하는 소스 플러그인을 검증했다. 플러그인 버전은 `0.1.0`, 엔진 버전은 `2.0.0`이다. 이 기록은 GitHub Release 게시나 모든 호스트에서의 설치 완료를 뜻하지 않는다.

## 환경과 자동 검사

Windows, Python **3.12.12**, uv **0.12.17**, Codex CLI **0.161.0**, Claude Code **2.1.293** 환경에서 실행했다.

```text
tests/test_plugin_runtime.py
tests/test_plugin_bundle.py
tests/test_agent_render.py
tests/test_codex_bundle.py
tests/test_portable_launcher.py
```

위 묶음은 **54 passed, 2 skipped, 16.20초**였다. 두 건은 Windows 심볼릭 링크 생성 권한에 따른 생략이며 통과로 세지 않는다. 새 런타임·플러그인 빌더·해당 테스트 및 소스 묶음 빌더에 대한 Ruff 검사도 통과했다. 전체 프로젝트 회귀검사 결과로 확대 해석하지 않는다.

## 압축 해제한 묶음의 실제 실행

시험 ZIP의 SHA-256은 `746e41c7faf67cdb3b56c5213e3f6ad5bee7a86fb3887eebab8dedf88a054074`이며, manifest의 공개 파일 수는 **52개**였다. 이는 해당 시험 스냅샷을 식별하며 이후 다시 빌드한 ZIP의 해시와 동일하다고 가정하지 않는다. 한글과 공백이 있는 경로에 압축을 해제하고, 별도 작업 폴더에서 실행한 결과를 `qa-summary.json`에 기록했다.

| 시나리오 | 결과 |
|---|---|
| 외부 캐시에서 초기 환경 준비 | 종료 코드 0, `status: ready` |
| `plain`, `ib-report`, `ib-memo`, `business-report`, `office-letter`, `meeting-minutes`, `term-sheet` | 7개 모두 엄격 변환 성공, `stage: complete`, `status: ready_for_review` |
| 확정 조건 비교값 불일치 | 종료 코드 1, `stage: expected_terms`, DOCX 미생성 |
| 플러그인 설치 폴더 안으로 출력 시도 | 종료 코드 1, `stage: runtime`, 거부 |
| 시험 전후 설치 파일 스냅샷 비교 | 변경 없음 |

생성 성공과 `ready_for_review`는 페이지 검토 완료를 뜻하지 않는다. 실제 거래 자료는 사용하지 않았다.

최종 패키지 재검토 대상은 `plugin-20261008T074327Z-84dc6c8c/ib-report-formatter-0.1.0.zip`이며 SHA-256은 `6383a38523594c7faf22265721901bd3570c7675a432466646c63301880bb693`이다. 공개 파일 **53개와 manifest 1개, 총 54개 항목**을 포함한다. 독립 검토자가 파일 크기·해시·해당 시점의 소스 바이트 일치 및 `.plugin` 파일과 ZIP의 바이트 동일성을 확인했다. 최초 실행 시험 묶음 이후의 변경은 안내 문서 수정과 기존 안내 추가이며 런타임·엔진 변경은 없다. 이 패키지 검토와 아래 작성 내용 검토는 별개다.

## 호스트 인식

- Claude Code에서 압축 해제한 폴더를 `--plugin-dir`로 지정했을 때 플러그인 세부정보에 `ib-document`와 `setup` 스킬이 로드되었다. 명시한 매니페스트 경로의 엄격 검증도 통과했다.
- Codex CLI에서 읽기 전용 `-c` 마켓플레이스 설정 재정의로 목록을 조회했을 때 플러그인과 버전이 인식되었다.
- 위 결과는 로컬 탐색·인식 시험이다. 사용자의 전역 플러그인 설정을 바꿔 영구 설치하거나 네이티브 GUI 설치를 검증한 결과는 아니다.

## Codex 작성 스킬 실행 평가

Codex 작성 에이전트가 새 플러그인 스킬을 읽고 가상 `brief.md`, `house.yaml`, `expected-terms.json`에서 텀시트를 새로 작성했다. 근거 목록 15행을 정리하고 제공된 기준 5개를 보존하면서 원문에 근거한 16개 변수 비교 기준을 구성했다. `plugin_runtime.py render`를 플러그인 외부 작업 폴더에서 실행했으며, 새로운 외부 캐시에 잠긴 의존성 16개를 설치한 뒤 첫 시도에 성공했다. 기존 프로젝트 가상환경은 렌더링에 사용하지 않았다.

- 종료 코드 0, `stage: complete`, `status: ready_for_review`.
- 엄격 변환·구조 검사에서 진단·구조 이슈·경고가 모두 비어 있었고, 조건 비교 16개가 일치했다. 수정·재시도는 0회였다.
- 작성 에이전트의 별도 내용 대조 단계에서는 DOCX XML의 원문 15개 조건, 기관 공통 문구, 미치환 변수 부재를 확인했다. ABCP 일정·발행금리와 주선수수료 등 미확정 조건은 확인사항으로 남겼다.
- 기관 파일 사본은 원본과 동일했으며, 원자료와 검사한 플러그인 설정·스킬·런처 파일의 실행 전후 해시도 동일했다.
- 선언된 산술 검사나 상환스케줄이 없으므로 산술 검증 통과를 주장하지 않는다.

이후 독립 검토자가 원자료 15개 조건을 초안·근거 목록·질문 목록·DOCX와 직접 비교해 통과로 판정했다. 제공된 기준 5개가 16개 조건에 그대로 유지되고, 기관 문구 3개가 정확히 보존되며, 미확정 금융조건이 임의 확정되지 않았음을 확인했다. 원자료 4개와 스킬·런처·산출물의 해시를 대조했고, 구조 감사를 다시 실행한 결과가 저장된 결과 및 표준 출력과 일치했다. 이 판정은 해당 가상 예제의 내용·구조 검토이며 금융·법률 승인이나 시각 검토는 아니다. 스킬 실행 성공은 호스트의 플러그인 자동 발견·UI 등록 시험과도 구분한다.

## 별도 검증이 필요한 범위

Claude Code 모델을 통한 작성 실행, 네이티브 GUI 설치, Claude 웹·Cowork의 `.plugin` 가져오기, macOS·Linux 실행, Word의 모든 페이지 시각 검토는 수행하지 않았다. 실제·예상 페이지 수와 Word 버전도 확인하지 않았다. XML 텍스트 대조는 시각 검토가 아니다.

사용·설치는 [플러그인 안내](plugin-guide.md), 재생성은 [배포본 빌드 방법](distribution-build.md)을 참고한다. 이후 배포본 검증에는 새 ZIP 해시와 실제 수행한 호스트·모델·페이지 검토 범위를 추가해야 한다.
