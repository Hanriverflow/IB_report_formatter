# Markdown→Word 전용 엔진 구현계획

## 목표와 확정 사항

- Word→MD 자체 개발은 사용자 결정으로 폐기한다. CLI·파서·OMML 역변환·Markdown 역렌더러·왕복 검사 및 전용 테스트를 제거한다.
- Markdown→Word는 기존 IB 보고서와 회사 대외공문·업무보고·회의록을 한 렌더링 경로로 지원한다.
- 이 계획은 2026-09-14 사용자의 계획 작성 및 구현 요청에 따라 실행한다. 기존 분석서의 Word→MD 유지 권고는 폐기 결정으로 대체된다.
- 기존 미추적 보고서·사용자 파일은 변경하지 않는다. 제거 이전 소스는 HEAD `d819bbb` 및 `codex/archive-word-to-md-d819bbb`에서 복구할 수 있다.

## 구현 범위

1. **정확성 및 공통 모델:** 빈 표 셀·이스케이프 파이프를 보존하고, 실제 숫자 출력 경로를 수정한다. 문서 데이터 모델을 파서에서 분리한다.
2. **프로파일·설정:** `ib-report`(기존 기본), `ib-memo`, `plain`, `office-letter`, `business-report`, `meeting-minutes`를 제공한다. CLI > frontmatter > 프로파일 기본값 순서로 적용한다. 요청별 불변 스타일을 사용하며 전역 객체를 교체하지 않는다.
3. **단일 조립 경로:** CLI·Python API·레지스트리가 같은 렌더러와 옵션을 사용한다. 머리말·쪽번호 누락을 고치고 표지/목차/면책 선택을 통합한다.
4. **일반 업무문서:** A4·중립 메타데이터·공문 수신/참조/문서번호/발신인/붙임, 업무보고 작성정보, 회의록 참석정보, Word 네이티브 다단계 목록을 제공한다.
5. **IB 및 공통 문서 품질:** 금융표 종류·열 의미·단위·출처·기준일·기준 시나리오를 명시할 수 있게 한다. 반복 표 머리행, 행 분할 제어, 가로 표, 링크·각주 입력을 보강한다.
6. **폐기·검증:** Word→MD를 제거하고 DOCX 구조 검증으로 대체한다. 엄격 검사에서 렌더링 오류와 중요한 입력 손실을 성공으로 처리하지 않는다.
7. **배포 준비:** 버전 2.0.0으로 갱신하고 README 쌍·AGENTS·변경이력·패키지 설정·예제·검증 결과를 동기화한다.

임의의 회사 DOCX 양식 자동 이해, 신규 차트 엔진, 네이티브 편집형 차트, AI 작성 스킬 배포, PDF 배포 자동화는 이번 구현 범위에 포함하지 않는다. 이번에 만드는 공통 계약을 사용해 후속 기능으로 확장한다.

## 구현 순서와 확인 기준

| 순서 | 작업 | 확인 기준 |
|---|---|---|
| 1 | 현재 테스트 기준선 확보, 결함 회귀 입력 추가 | 기존 기준선과 실패 재현 기록 |
| 2 | 모델·프로파일·파싱 정책 | 프로파일 우선순위, 구조화 메타데이터, 원본 셀 대응 |
| 3 | 조립 통합·문서별 구성·Word 요소 | 같은 옵션의 호출 경로 일치, 일반 문서에 IB 문구 없음 |
| 4 | MD→Word 검증 대체 및 역변환 제거 | 운영 코드에서 폐기 모듈 참조 없음, 남은 테스트 정상 |
| 5 | 기능 통합·문서·샘플 | 전체 테스트, 변경 코드 정적 검사, 샘플 생성·DOCX 구조·페이지 확인 |

## 설계 세부

- `document_model.py`: 공통 데이터 클래스. `md_parser`의 기존 모델 import는 재노출해 유지한다.
- `document_profiles.py`: 프로파일, 옵션, 메타데이터 검증, 테마 로딩. 프로파일별 입력 추정 규칙을 분리한다.
- `render_styles.py`: 기존 스타일 타입과 불변 설정. 기존 정적 렌더 도우미를 안전하게 재사용하기 위해 render 범위의 ContextVar로 스타일을 전달한다. `STYLE`은 호환 접근자이며 요청 간 공유 객체를 변경하지 않는다. 함수 기본 인자·클래스 캐시에 스타일 값을 고정하지 않는다.
- `ib_renderer.py`: 공통 요소 렌더링과 하나의 문서 조립 함수. 기존 클래스 이름은 호환 API로 유지한다.
- `office_layout.py`: 회사 업무문서 머리 부분·붙임/발신 부분 및 네이티브 번호 정의.
- `docx_audit.py`: Word→MD 파서 없이 생성된 DOCX의 오류 표시, 구조, 표, 필드 등을 검사한다.
- 표 옵션은 frontmatter의 `tables` 목록으로 본문 표 순서에 대응시킨다. 지정한 표만 명시적 정책을 적용하고, 일반 프로파일은 금융 자동 추정을 하지 않는다.

## 검증 정책

- 테스트 실행 임시 경로는 Windows 절대 경로로 매번 새로 생성한다.
- Python 3.8 문법/API 호환을 유지한다. 실제 테스트 인터프리터는 프로젝트의 Python 3.12이다.
- 표·메타데이터·숫자·프로파일 격리·CLI/API·번호·각주·오류 상태를 실제 변환 경로로 검사한다.
- 기존 출력의 명시적 수정: 빈 셀 보존, 금융 숫자 포맷, CLI 머리말/쪽번호, 면책 토글, 표 페이지 속성. 그 외 IB 기본 시각 정책은 유지한다.
- 삭제한 테스트 수를 신규 기능 품질로 오해하지 않도록 기존 기준선·최종 개수를 별도로 기록한다.
- DOCX의 무작위 북마크 ID와 날짜를 제외한 의미·구조를 비교하고 실제 글꼴·페이지 환경의 한계는 결과에 기록한다.

## 완료 기록

- 1~5단계 구현 및 검증 완료. 코드·문서·샘플·구조 검사·정적 검사·패키지 빌드/설치와 실제 Word 페이지 검증을 마쳤다.
- 최종 테스트 251개 통과(유지/조정한 기존 183개 + 신규 68개). 변경 전 284개 중 역변환 전용/관련 101개는 기능 폐기에 따라 제거했다.
- 변경 Python·테스트 Ruff 통과, 핵심 9개 모듈 mypy 통과, wheel 엔진 14개 모듈 Python 3.8 문법 검사 통과.
- 버전 2.0.0 wheel/sdist를 빌드하고 저장소 밖 별도 환경에서 설치된 CLI로 공문 생성·구조 검사까지 확인했다.
- **페이지 검증 완료:** Word의 페이지 EMF 출력으로 6종 프로파일과 긴 표·가로 표의 총 14페이지를 확인했다. 목록·표 편집 후 저장/재열기에서 번호 이어짐, 링크·각주 보존도 확인했다. PDF 자동 배포는 구현 범위 밖이며 회사별 실양식 승인·모든 문서의 무조건적 인쇄 품질 보장을 의미하지 않는다.
- 완료 점검에서 긴 YAML·입력 프로파일 우선순위·한글 인코딩·상대 이미지 경로·본문/제목/표의 각주·목차 필드 갱신·중립 제목 스타일·IB 메모 간격·가로 구역 머리말을 추가 보완했다.
- 자세한 명령·증거·제한은 [검증 결과](verification-20260914.md)에 기록했다.
