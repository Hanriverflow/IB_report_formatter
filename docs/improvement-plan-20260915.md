# 실사용 공문 실패에 따른 개선계획

상태: 구현 및 검증 완료. [실제 검증 결과](verification-20260915.md)에 테스트·페이지 검토·해시를 기록했다.

## 원인과 가설

1. 문장 중간·표 셀의 `<br>` 처리가 인라인 파서에 없고 문단 끝 처리에만 있어 HTML 토큰이 출력된다. 실제 MD → 모델 → DOCX 회귀 테스트로 재현한다.
2. 과도한 검은 사각형은 실사용 문서를 별도로 보정한 코드가 Normal과 본문/표 스타일에 keepLines를 일괄 설정한 결과다. 인쇄용 글머리표와 편집용 문단 표시를 구별해야 한다. 엔진의 필요한 제목 페이지 제어까지 일괄 제거하지 않는다.
3. 공문 구성과 별첨 시작 위치를 엔진에서 표현하지 못해 개별 보정에 의존했다. 공문 기본 서식과 명시적 별첨 계약을 단일 렌더링 경로에서 지원하고, 구조 검사와 실제 페이지 검사 결과를 분리한다.

## 구현 및 완료 기준

- 인라인 줄바꿈: 본문·강조·제목·목록·표에서 `<br>`, `<br/>`, `<BR />`를 실제 Word 줄바꿈으로 출력한다. 코드/이스케이프와 링크 주소·금융 숫자는 보존한다.
- 공문: 회사명, 수신/참조/제목 탭 정렬, 편집 가능한 붙임 번호, 끝 표기, 발신/시행/연락처를 정돈한다. `letter.appendix_heading`에 해당하는 유일한 H1 앞에서 공문을 닫고 별첨을 새 페이지로 시작한다. 없는/중복 경계는 저장 전 거부한다. 별첨 포함 여부와 증빙의 실제 존재를 자동 추정하지 않는다.
- 진단: 불필요한 Normal 문단 묶음 설정과 편집기호를 일으키는 유효 페이지 제어 개수를 보고한다. 경고는 구조 오류/시각 합격 판정이 아니다.
- Word QA: 출력 디렉터리 재사용 금지, 기대 페이지 수 검사, 입력/출력 해시·Word 버전 기록, 육안 검토 상태 `pending`을 명시한다. 읽기 전용으로 작업하며 사용자 앱/프린터 설정은 변경하지 않는다.
- 검증: 실패 재현 → 수정 → 전체 테스트·정적 검사·배포 검사. 가상 회사 예제로 기본 공문과 별첨 공문, IB/일반 문서를 실제 Word에서 렌더하고 모든 페이지를 확인한다.

실제 거래명·금액·계좌·연락처·원본 파일은 코드, 테스트, 샘플 및 배포물에 넣지 않는다. Word→MD 폐기 원칙은 그대로 유지한다. 커밋·push·외부 배포는 하지 않는다.
